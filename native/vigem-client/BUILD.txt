build.ps1 invokes the native build before the full suite and frozen build.

Changes:
- JoinedX360.h: owned Windows thread, startup publication barrier, overlapped I/O
  wait on completion/cancel events, CancelIoEx plus cancellation drain, join before
  releasing callback/target/client. No detached Xbox notification thread.
- Exports ABI=2, stop with checked result and a thread error code.
- Terminal driver errors stop the receiver instead of spinning.
- CheckedIo.h handles immediate success/failure and waits only for IO_PENDING.
  Connect/add/remove/update share it; all update completion failures propagate.
- DS5Light uses Xbox only: unused DS4 functions, thread/event fields and the
  DS4 target table are removed. DS4/async-add/old unregister exports are absent.
- TestNotificationIo.h is compiled ONLY into a separate work/ test DLL. The
  production DLL has no test exports. Tests use real Windows threads/events and
  ctypes callbacks but never open a driver.

Input report conversion and submission remain direct calls with checked I/O.
No sockets, subprocesses, periodic device search or audio changes.
Bundled source, local DLL hash and LLVM/MinGW notices accompany distribution.
Stop waits for actual completion, not a fixed delay. If a broken kernel driver
never completes cancellation, the worker remains in stopping state rather than
freeing live native memory. Hardware cancellation timing remains to be tested.

ABI2 is required by the current Python wrapper so old pre-fix client DLLs are rejected.
